# 2026-09-16 工作日志

## 修复：相邻办公室之间的墙体闪烁（z-fighting）

用户反馈：「读取文件夹里的项目，我发现相邻的办公室之间的墙体闪烁」。

### 一、根因（脚本实测，非推断）

新建 `_verify/verify_wall_zfight.mjs`：读浏览器里**真实场景图**（`__boardDebug.scene`），
对每间房的 2.8m 高墙盒算世界 AABB，找出**不同房间之间「严格共面（<1mm）+ 体积重叠」**的墙对。

修复前实测 **5 处大面积共面**：

| 共墙 | 房间对 | 共面面积 |
|---|---|---|
| x=15.6 | CRO ↔ CMO | 12.88 ㎡ |
| x=23.8 | CMO ↔ CTO | 18.48 ㎡ |
| x=19.4 | COO ↔ CEO | 18.48 ㎡ |
| z=11.0 | CPO ↔ 会议室 | 15.68 ㎡ |
| z=16.4 | 会议室 ↔ CFO | 14.56 ㎡ |

成因：错落布局里 5 对相邻房共享同一条墙线，每间房都按"墙心落在房间边界线上"生成 0.15m 厚墙盒
→ 两条墙盒完全重合、六面严格共面 → 深度值相等 → GPU 每帧重新争抢。
因为各房墙色（`ROOM_WALL_COLORS`）不同，闪烁表现为**墙面颜色跳变**。

### 二、修法（自适应，非硬编码坐标）

`createRoom()` 内新增：
1. `sharedNeighbor(name)` — 查本房某条墙线是否与另一间房的墙线数值重合（<1e-6）；
2. 是共墙 → 两侧按 `zone.id` 字典序分别内收 **8mm / 3mm**（`WI_A`/`WI_B`），墙心错开 11mm；
3. 墙**两端**精确落在「房间边界 − 该墙内收量」上（两端各自算，避免两端内收量平均后重新相等）；
4. 门洞中心以 `edgeStart` 作原点反算 → **恒等于 `doorPos`**，与内收量无关（门扇/门牌不错位）；
5. 门牌贴墙距离 `off` 同步减该墙内收量。

余量：相机 near/far = 0.5/75，24 位深度在 25m 处精度 ≈0.07mm → 11mm = 150 倍（实测残余最小面间距 5mm = 68 倍）。墙厚不变、净尺寸只少 3~8mm。

### 三、踩坑

- **`_mine < nb` 数字比字符串 → NaN → false**：共墙两侧都取了 WI_B（同值）→ 端面依旧重合。
  改成 `_mine < _ids.indexOf(nb)` 才生效。
- **端面重合**：墙长若只按「d − 两端内收之和」对称算，两端内收量平均后可能与邻房相等 → 必须两端各自精确落位。
- **检测脚本判共面只能取 X/Z 轴**：y 恒为 0~2.8，算进去会把"十字交叉但不共面"的墙全误报（35 条假阳性 → 8 条真）。
- 门洞净空射线首个命中 0.57m = 关着的门扇外表面（0.6−0.03），本来就如此，不是新问题。

### 四、验收

| 项 | 修前 | 修后 |
|---|---|---|
| 共面墙对（>1㎡） | **5** | **0** |
| 残余共面（≤0.53㎡，框柱被包住） | 3 | 0 |
| X/Z 面最小间距 | 0（共面） | 5mm |
| 页面报错 | 无 | 无 |
