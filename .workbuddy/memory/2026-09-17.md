## 二、任务接入引擎 taskboard v1.0（agent 无关版）

### 需求
「各个 AI Agent 里完成/未完成的任务都能录入看板、随时查看、最好能上 Docker；
配置重新给一套，不要只绑定某个 agent、不要写死路径。」

### 结论：旧管线三个死穴
1. `extract-tasks.py` 只读 `~/.workbuddy/task_log.md` + `CONTEXT_INDEX.md` → **绑死 WorkBuddy**。
2. `import_inbox.py` 只认 ```board 格式的 .md + 固定 inbox 路径 → **绑死格式与路径**。
3. 直接改 `tasks-data/tasks.js`：多 agent 并发写会互相覆盖；无法按条件改/删。

### 交付（全部新增，未破坏旧管线）
| 文件 | 作用 |

| `board.config.json` | **唯一配置**；全相对路径，零 agent 专属目录；`BOARD_*` 环境变量可覆盖 |

| `说明书-看板接入.md` | 10 章说明书（含表结构、API、数据流、限制） |

### 核心设计
- **两条通道**：HTTP（`POST /api/tasks`）+ 文件投递箱（`data/inbox/`，30s 自动扫）。
  只要 agent 会"发请求"或"写文件"任一，就能接入。
- **归一化层 `model.py`**：`name/task/标题`→title、`zone/部门`→dept、`marketing/营销`→cmo、
  `已完成/closed/done:true`→done、`urgent:true`→high、`doing/wip`→in_progress。
  **title 是唯一必填**。猜不出部门 → `_unassigned`（中控台「记忆派生任务」可见）。
- **SQLite WAL + `UNIQUE(dept, dedup_key)`**：重复上报 = 更新，不会重复卡片。
  不用"直接改 JS 文件"就是为了并发安全。
- **看板侧**：数据源优先级 `?api=` > 同源自动探测 > `file://` 静态回退；
  每 20s 轮询（`?poll=` 可调）；点状态/删除**立即回写** `PATCH/DELETE`；
  左下角指示灯 🟢/🔴，卡片显示来源 agent 标签，图例显示「未完成/总数」。

## 三、taskboard 收口：控制台噪声归零 + 解析器修正 + 隐私面收紧

接第二节，把「接入引擎」从"能用"推到"可长期挂着"。三件事，都是实测驱动。

### 3.1 干掉盲探测（控制台 404 噪声 → 0）

- **现象**：`verify_v5.mjs` 在 8934 静态预览上报 2~4 条 `404 tasks.json`。
- **根因**：原设计是「页面用 http 打开就去试同源 `/api/tasks.json`」→ 普通静态服务器上必然 404，且轮询会反复刷。
- **修法（关键决策）**：**不做同源盲探测**，改成"谁托管谁知道"——
  `server.py::_inject_hint()` 在返回 `.html` 时往 `</head>` 前注入
  `<script>window.__BOARD_API_HINT=location.origin;</script>`；静态打开的页面没有该变量 → **一个请求都不发**。
  看板侧 `BOARD_API_BASE` 优先级改为 `?api=` > `__BOARD_API_HINT` > 空。
- **顺带**：`_apiProbed` 换成**连续失败计数**（`_apiFails ≥ 3` 才停轮询），指示灯可点击重试；
  加内联 SVG favicon 消掉浏览器默认的 `favicon.ico` 404。
- **结果**：`probe404.mjs` 在 8934 与 8787 双向实测 → **0 报错**（`verify_v5.mjs` 控制台 8 日志/0 警告/0 报错）。
- ⚠️ 变量声明踩坑：`_apiEverOnline` 用了但 `var` 里没声明 → `<script type="module">` 严格模式下会抛
  ReferenceError。**改这类模块作用域代码后务必实跑，别只看 diff。**

### 3.2 解析器修正（`ingest.py`）

- **bug1 元数据漏进标题**：`- [x] 做完的事 | s:done | p:high` → 标题带着整串 `| s:done | p:high`，
  且 `p:high` 完全没生效。根因：`_CHECK` / `_BULLET` / 裸文本分支直接取整行当标题，**没走 `_kv_segments`**。
- **bug2 `dept:` 语义冲突**：`_kv_segments` 里 `dept` 被映射到 **collaborators**（历史 board-export 约定），
  与任务级 `dept`（归属部门）同名不同义。
- **修法**：新增 `_split_title_meta()`，所有分支统一"先摘 `|` 段再当标题"；
  行内别名拆分为 `dep/collab/协作` → collaborators，`dept/zone/team/room/部门` → **dept**；
  空标题行（`- [x] | s:done`）丢弃不造空卡片。
- **固化**：新增 `_verify/test_ingest_parse.py`（**30 项，秒级**），改解析先跑它。
  踩坑：第一版测试期望写错（`[cpo] ... | dep:cfo,cto` 的 dept 应为 `cpo`），是**测试错不是代码错**——
  写测试时先想清楚"正确行为"再写期望。

### 3.3 隐私面收紧（静态托管黑名单）

- **问题**：`staticRoot: "."` 会把整个仓库目录托出去。原黑名单只挡前缀，
  于是 `inbox/*.md`（任务清单）、`_shots/`（截图）、`*.bak`（整份备份）、`*.md` 文档全部可直接下载。
- **修法**：`_denied()` 改为「`/` 开头按**前缀**、其余按**子串**」（因为备份名是 `xxx.html.bak_pre_zfight` 这种把
  `.bak` 放中间的形态，纯后缀匹配漏掉）；黑名单补齐 `/inbox/ /_shots/ /agent-templates/` +
  `.bak .db .py .md .env .log` 等。**只放行看板真正要的 `.html` / `.js` / 模型文件。**
- 端到端脚本加 6 条隐私校验（inbox / _shots / 配置 / .bak / .md / Dockerfile 全部 403）。

## 5. 认领协议（A+B 中间态）落地 —— 用户三问的第 2、3 问

**用户原话**：「1，导入任务我明白了；2，至于导入到哪个主管部门或有其他部门的如果导入前我让agent判别了，是否能更新 any-agent-prompt.md 让其适配？3，按A+B的中间态实践一下」

### 5.1 第 2 问：agent 侧部门判别 ✅

- `any-agent-prompt.md` + `SPEC.md` 增 §「上报前先判『这条归谁』」三步：① 谁验收→写 `dept` ② 谁给料→写 `collaborators` ③ 判不出→**不写 dept**（引擎会猜并打标）。口诀：`dept`=谁验收，`collaborators`=谁给料。
- 引擎侧新增 **`dept_source`** 判别字段：`expert`(agent 写了) / `guessed`(引擎按标题关键词猜的) / `none`(没认出来)。
  - 看板对 `guessed` 的任务打灰色**「部门待核」**标 → 人工一眼看出哪些要复核。
  - 另收 `dept_reason` 字段（让 agent 写判断理由）。
- 好处：agent 判得准就用 agent 的；判不出也不卡住入库；**人始终知道哪些是机器猜的**。

### 5.2 第 3 问：A+B 中间态 = 认领协议 ✅

设计要点（**保留人工审核关口**，这是用户明确偏好）：

| | 谁做 | 结果 |
|---|---|---|
| 提议 | agent `POST /api/tasks/<id>/claim` | 任务**保持 `todo`**、`assignee` 空 —— **绝不自动开工** |
| 批准 | **人在看板点击** `POST /api/claims/<id>/approve` | 才转 `in_progress` + 落 `assignee` |

- 新表 `claims`（proposed / approved / rejected / withdrawn），**append-only 审计**；`UNIQUE(task_id, agent)` → 重复提议＝更新而非新增。
- 引擎铁律：**已 approved 的再提议不得回退成 pending**（返回 `already_approved`，只更新 note）—— 这是测试中发现并修掉的真 bug（否则 agent 可自我撤销人的批准）。批准某人时自动驳回其他 proposed（理由「已被 xxx 认领」）；驳回已批准的 → 任务回 `todo` 并清空 assignee。
- 看板 UI：左下 `#claim-badge`(🔔 N 待批) + `#claim-tray` 浮层（显示理由 + 批准/驳回）；卡片显示 `🔔 N 人申请` + ✓/✕/↩。
  - **刻意设计**：多申请人时点卡片 ✓ **不代选**，而是展开浮层让用户自己挑；单申请人则直接批准。
  - **刻意设计**：20s 轮询 → 外部 agent 的申请 ≤20s 出现在看板（不追求实时推送）。
- 新增 `agent-templates/claim-poll.py`：给"能跑命令的 agent"的一站式认领助手（`ask/claim/state/queue/withdraw/report`），纯 stdlib，读 `BOARD`/`BOARD_TOKEN` 环境变量。
- CLI 新增：`claim` / `claims` / `approve` / `reject` / `withdraw` / `queue`；`ls` 支持 `--claim` / `--agent`。
